# FLOCK（仮称）群れシミュレータ 開発設計書

> **版数:** v0.2（2026-10-30）  
> **位置づけ:** 基本構想・画面/操作仕様・集団行動アルゴリズム・実装計画  
> **対象:** スマートフォン優先の3D Webアプリ  
> **方針変更:** ユーザーが群れを誘導する方式から、**自律的な群れにユーザーが干渉する方式**へ変更

---

## 1. 企画概要

### 1.1 コンセプト

イワシの魚群やムクドリなどの鳥群が、自律的に移動・旋回・集合・分裂する様子を眺めながら、指で触れたり、障害物を置いたりすることで群れの反応を楽しむインタラクティブ・シミュレータ。

**プレイヤーは「リーダー」ではなく「環境の一部」になる。** 群れは常に自律的に動き、プレイヤーが何もしなくても成立する。触れた箇所を起点に反応が連鎖し、障害物の周りを流体のように迂回し、再び集合する様子を主役にする。

### 1.2 体験の柱

1. **眺める**：指示なしで群れが自然に動き続ける。
2. **驚かせる**：触れた場所の個体が逃げ、その影響が隣へ伝わる。
3. **実験する**：障害物の形・位置・大きさを変え、群れの反応を比較する。
4. **育てる**：周辺の小集団が合流し、群れが徐々に大きくなる。
5. **見入る**：群れが分裂・回転・再集合して複雑な形を作る。

### 1.3 製品の位置づけ

- ゲーム的な勝敗や得点より、**自然現象の観察と操作による発見**を優先。
- 学習用途にも転用できるが、初期版では理科教材としての厳密な生態再現を保証しない。
- 画面を開いてすぐ楽しめる。登録・サーバー通信・チュートリアルの長文説明を不要とする。
- **シミュレーション上の個体は人工モデルであり、実際の魚や鳥の生態を厳密に再現したものではない。**

### 1.4 MVPで実現すること

**必須：** イワシモード、自律群泳、接触による忌避、球体障害物の配置・移動・削除、自然な迂回と再集合、仲間の自動合流、個体数表示。

**後続：** 壁/柱などの形状、鳥モード、高度な群れの分裂表現、録画・共有、研究・観察用パラメータUI。

## 2. 体験フロー

### 2.1 起動～5分の典型例

| 時点 | 表示・現象 | ユーザー体験 |
|---|---|---|
| 開始直後 | 約12匹のイワシが自律遊泳 | 操作せず眺められる |
| 10～30秒 | 画面外から小さな魚群が近づく | 合流する様子を発見 |
| 指でタッチ | 接触点近くの魚が素早く離れる | 群れに穴が開くような動き |
| 指を動かす | 逃避反応が指の軌跡に沿って広がる | 群れの内部をかき分けられる |
| 障害物を設置 | 群れが左右・上下を迂回 | 形が伸びたり分かれたりする |
| 障害物を移動 | 反応が連続的に変化する | 新しい形状・流れが生まれる |
| 3～5分 | 数百匹規模に成長 | 大群の複雑な動きを鑑賞 |

※時刻・個体数は仮設定であり、端末性能と実機調整により変更する。

### 2.2 自律移動の原則

- 操作入力が**ゼロでも**継続する。
- 画面中央の見えない単独リーダーに全個体が追随する方式にはしない。
- 個体同士の局所相互作用を主体に、弱い環境流・緩やかな移動方向の変化・行動ノイズを加える。
- 一定周期で強制的に同じパターンを繰り返さない。
- 狭い世界境界で跳ね返るような不自然な挙動を避ける。

## 3. UI・操作仕様

### 3.1 画面構成

```text
┌─────────────────────────┐
│  FLOCK  128        ⚙    │
│                         │
│        自律的な魚群      │
│         3D空間          │
│                         │
│     ●  ← 障害物         │
│         魚群が迂回      │
│                         │
│  [触れる] [障害物] [観察] │
└─────────────────────────┘
```

- 世界を全面表示し、UIを最小化する。
- 初期モードは**「触れる」**。ただし未接触時は純粋な自律観察。
- 画面を隠す操作パネルは常時表示せず、必要時だけ展開する。
- 個体数は小さく表示。FPS・秩序パラメータなどは開発者表示でのみ確認する。

### 3.2 操作モード

| モード | 1本指タップ | 長押し・ドラッグ | 補足 |
|---|---|---|---|
| **触れる**（標準） | 接触点に短い忌避刺激 | 指位置に沿って連続忌避 | 群れの進路は指示しない |
| **障害物** | 障害物を1個設置／既存物を選択 | 選択物を移動 | サイズ変更・削除をサブUIで操作 |
| **観察** | 群れには干渉しない | 群れには干渉しない | スクリーンショット・鑑賞向け |

**衝突回避ルール：** 障害物モードでは指が群れに触れても忌避刺激を生成しない。触れるモードでは障害物を新規作成しない。

### 3.3 タッチによる忌避

- **短いタップ**：点状の刺激を一度与え、近くの個体が離れる。
- **長押し**：接触位置を中心に一定範囲の忌避が持続。半径はゆるやかに立ち上がり、急激なジャンプを防止。
- **ドラッグ**：指の軌跡をなぞるように忌避領域が移動する。
- **指を離す**：忌避場は約0.2～0.6秒で減衰し、個体は通常行動へ回復する。
- 逃避は近くの魚から始まり、遠くの個体は隣接個体の方向変化に反応する。
- 指が画面上にあっても、実際の魚群が離れていれば反応しない。
- 指の位置に魚が吸い寄せられたり、全員が一斉に同じ方向へ逃げたりしない。

**演出方針：** 原則として派手な衝撃波エフェクトは描かず、魚の動きそのもので刺激を伝える。デバッグ時のみ刺激半径を可視化できる。

### 3.4 障害物の設置・編集

**MVPの形状：球体のみ。** 壁・柱・トンネルは次段階で追加する。

- 障害物ボタンでモード切替。
- 空き場所のタップで、カメラにほぼ正対した基準奥行き面に球体を設置する。
- 設置直後は選択状態。ドラッグで左右上下に動かせる。
- 画面内のサイズスライダーで半径を変更。
- 削除ボタンで選択した障害物を削除。
- 「全消去」で配置した障害物のみリセット。群れは維持。
- 初期上限は**5個**。上限時は追加ボタンを無効化し理由を表示。
- 画面外への誤配置を避けるため、配置可能領域を画面周辺から少し内側に制限。
- 初期版の奥行きは固定。将来、奥行きスライダーや3Dギズモを検討。
- 球体は半透明／淡い発光／低彩度のいずれかから、視認性と世界観の両立を優先して選択する。

### 3.5 カメラとジェスチャー

- カメラは群れの中心・広がりに合わせて**ゆっくり追従・ズーム**する。
- 障害物はワールド座標に固定し、カメラが動いても世界内の位置を保持。
- 2本指ピンチはカメラズームとして扱い、忌避刺激や障害物設置を起こさない。
- 1本指での視点回転はMVPでは採用しない（忌避ドラッグと競合するため）。
- 「視点を戻す」操作は設定メニューに用意。
- `pointercancel`、画面回転、アプリ非表示への移行時は入力状態を安全に解除する。

### 3.6 初回ガイド

起動時のみ、短いオーバーレイで「魚は自動で泳ぎます。触れると逃げます。障害物も置けます。」と表示。1回触れたら消え、設定から再表示可能。

## 4. 集団行動モデル

### 4.1 採用方針

**Vicsek型の局所整列＋Boids型の分離/結合＋Couzin型の距離別優先順位＋環境忌避**を組み合わせる。

- **Vicsek型整列**：近傍の進行方向へ、ノイズを伴いながら向きを揃える。
- **分離**：近すぎる仲間から離れる。
- **結合**：適切な範囲で近傍の仲間に近づく。
- **距離別優先順位**：衝突の危険が高いときは分離を優先する。
- **環境忌避**：指・障害物・世界境界に対して局所的な反応を追加する。

**注意：** BoidsのAlignmentとVicsek型整列を独立した二重の力として加算しない。整列コンポーネントは1つとする。

### 4.2 個体状態

各個体 `i` について、以下を保持する。

```ts
type Agent = {
  position: Vec3;
  velocity: Vec3;
  heading: Vec3;
  speed: number;
  phase: number;          // 尾びれ・羽ばたき位相
  responseBias: number;   // 反応個体差
  stress: number;         // 忌避反応の減衰状態（0～1）
  flockId: number;        // 分裂・合流観測用（表示上の任意属性）
};
```

`position`、`velocity`は3Dワールド座標で管理。描画上の位置と物理上の位置を分離する。

### 4.3 近隣領域と優先順位

**外側からの概念的な3領域：**

1. 結合領域：仲間から離れすぎないよう弱く近づく。
2. 整列領域：仲間の向きに合わせる。
3. 分離領域：接近しすぎた個体を強く避ける。

近隣探索の結果を距離帯で分類する。領域は完全に排他的でも、重みを滑らかに切り替えてもよい。最終的には境界で動きが急変しない実装を選ぶ。

### 4.4 合成方向と運動制限

概念式：

\[
\mathbf a_i = w_s\mathbf S_i + w_v\mathbf V_i + w_c\mathbf C_i + w_t\mathbf T_i + w_o\mathbf O_i + w_e\mathbf E_i
\]

- `S`：仲間との分離
- `V`：Vicsek型の局所整列（**平均ベクトル長が小さい場合の不安定化を避ける**）
- `C`：仲間への結合
- `T`：指への忌避
- `O`：障害物への忌避
- `E`：環境流・緩やかな遊泳変動・世界境界

加速度・速度・旋回角速度に上限を設ける。物理演算は固定時間刻みで実施し、画面描画は補間する。

#### 整列の実装上の注意

古典的Vicsekモデルは定速・向き更新が中心である。一方、本アプリでは避障や逃避時の加減速・旋回制限が必要なため、**Vicsekをそのまま再現するのではなく、局所平均方向へのステアリングとして応用**する。研究用の厳密再現モードではない。

### 4.5 自律移動を生み出す環境要因

- 緩やかに時間変化する**低振幅の3Dフローフィールド**を適用する。
- 群れ全体の移動速度や方向は局所ルールから生じるようにする。
- 群れが画面外へ完全に消えないよう、**カメラ追従と弱いソフト境界**を組み合わせる。
- ソフト境界は近づくほど回避が増す。座標反転・画面端への瞬間移動は禁止。
- 鳥モードでは翼の傾き・滑空方向、魚モードでは体軸と尾びれ運動を進行方向へ連動させる。

## 5. 指への反応モデル

### 5.1 タッチを3D空間へ変換

タッチのスクリーン座標からカメラレイを作成し、**カメラにほぼ正対する基準奥行き面**との交点を取得する。そこに仮想的な「忌避球」を配置する。

- 指は2D座標で入力するが、実際の忌避は3D空間で評価する。
- 近くに見えても奥行きが大きく異なる個体は、通常は反応しない。
- 指の操作が直感とずれないよう、忌避球の半径と奥行き方向の厚みは別設定とする。
- 将来、スクリーン座標からのレイに沿った**円柱状の忌避体積**も選択肢として検討する。

### 5.2 忌避力

個体位置を `p`、刺激中心を `q`、距離を `d = |p-q|`、有効半径を `R` とする。

```text
if d >= R:
    touchAvoid = 0
else:
    strength = smoothstep(R, r_inner, d)
    touchAvoid = normalize(p - q) * strength * touchWeight
```

※`smoothstep`の引数順は実装ライブラリに合わせる。`r_inner < R`。中心でゼロ距離になった場合は、既存速度などを使って安全な退避方向を作る。

- 近距離ほど強いが、急激な力の発散は起こさない。
- 忌避力は横方向・上下方向への回避を許す。
- その場で瞬間的に反転することは禁止し、最大旋回角速度の範囲で避ける。
- 指の急移動時には刺激位置を補間し、途中の魚をすり抜けてしまう問題を防ぐ。

### 5.3 反応の伝播

反応が「群れの波」に見えるよう、触れた個体には一時的な `stress` を持たせる。

- 直接刺激：`stress` を増加。
- `stress` が高い個体：一時的に離隔距離・加速上限・警戒方向への重みを増加。
- 周辺個体：隣接個体の急旋回や速度変化に追従する。
- 時間経過：`stress` が減衰し、平常パラメータへ戻る。

**重要：** 反応は遠隔個体へ瞬時に伝達しない。近傍相互作用によって局所的に広がる。局所反応だけで魅力的な波が生じない場合に限り、短距離の警戒伝達を追加する。

### 5.4 避けるべき不自然な挙動

- 接触した瞬間に全個体が同時に方向転換する。
- 指を中心に綺麗な円形の穴が固定的に開く。
- 接触点から離れた個体まで一律に高速化する。
- 触れた後に魚が停止・瞬間反転する。
- 指が離れた瞬間に元の位置へ吸い戻される。

## 6. 障害物と回避アルゴリズム

### 6.1 障害物データ

```ts
type Obstacle = {
  id: string;
  kind: 'sphere';       // MVP
  position: Vec3;
  radius: number;
  enabled: boolean;
};
```

将来 `box`、`cylinder`、`arch` などを追加できる拡張可能な構造にする。

### 6.2 回避設計：位置だけでなく進行先を見る

障害物に近づいてから真横へ押し返すだけでは、衝突・張り付き・振動が生じやすい。

そこで、各個体の**現在位置・速度方向・短時間の予測進路**を使って回避方向を決定する。

1. 進行方向の前方にある障害物を探索。
2. 予測移動線分と障害物の距離を評価。
3. 危険と判断した場合、障害物の外周を回るような方向を選択。
4. 側方の空間が狭ければ上下方向へ逃げる。
5. 障害物を通過後、徐々に通常の分離・整列・結合へ復帰。

障害物の大きさには「魚体半径＋安全余裕」を加えた**拡張半径**を使う。めり込み防止の最後の保険として位置補正を行うが、通常の反応は事前予測で生じさせる。

### 6.3 群れの分裂・再集合

- 障害物に差し掛かると、局所回避によって自然に左右・上下へ分かれる。
- **分裂をアニメーションで強制しない**。個体の回避方向の差から結果的に分岐させる。
- 通過後は結合・整列が働き、二つの流れが緩やかに再集合する。
- 再集合までの時間は障害物の大きさ、群れの速度、密度、整列強度などに依存する。
- どうしても集団が永続的に離散する場合は、局所ルールを壊さない範囲で弱い長距離結合や離脱個体の再合流補助を設ける。

### 6.4 障害物を動かした場合

- 障害物位置を移動速度制限付きで更新。
- 移動障害物との相対速度を考慮し、未来位置への衝突を予測。
- 指で障害物を魚群の真上に重ねた場合は、個体が**急激に飛び散るのではなく最短方向へ退避**する。
- 障害物同士の重なりはMVPで許容するが、重なった物体が個体を閉じ込めても数値発散しないこと。

## 7. 群れの成長・小集団の合流

### 7.1 基本仕様

- 初期数：**12匹**。
- 別の小集団が世界の外縁から出現し、本体へ自律的に接近する。
- 新規個体が本体に十分近づき、一定時間同じ集団として行動したら合流完了と判定。
- 数値だけ先に増やすのではなく、**見た目の合流とカウンタの変化を一致**させる。
- 一定の個体数に達したら、成長ペースを抑えて見やすい密度を保つ。

### 7.2 成長ペース案

| 開始から | 目標個体数（例） |
|---|---:|
| 0秒 | 12 |
| 30秒 | 約30 |
| 90秒 | 約90 |
| 180秒 | 約220 |
| 270秒 | 約500 |

上記は**演出設計上の仮目標**。合流が画面内で確認できない速度で増やさない。端末の性能により上限を自動変更する。

### 7.3 群れが複数に分かれた場合

- 実際に分裂しても個体を消去しない。
- 画面上の表示数は生存している全個体数を示す。
- 分裂した小集団の追跡はシミュレーション補助用であり、群れIDに従わせて移動させるものではない。

## 8. 魚・鳥のモード差

| 項目 | イワシ（先行） | 鳥（後続） |
|---|---|---|
| 群れの密度 | 高い | やや低い |
| 自律的な移動 | 水中で3Dの帯・渦 | 空中で波・雲・帯 |
| 忌避 | 俊敏な側方・上下移動 | 旋回・上昇・下降 |
| 回避半径 | 相対的に小さい | 相対的に大きい |
| 個体アニメーション | 尾びれの左右運動 | 羽ばたきとバンク |
| 見た目 | 銀色の反射、青い水中 | シルエット、夕空 |
| 環境障害物例 | 岩・球体・柱 | 球体・塔・壁 |

共通エンジンに対して種別ごとのパラメータを注入する。**魚で成立したパラメータを鳥にそのまま流用しない。**

## 9. 画面デザイン・演出

### 9.1 ビジュアル

- UIは最小限。画面の主役は群れの連続運動。
- 海中は深い青～ターコイズの柔らかい奥行き表現。
- 小さな魚でも方向が分かるシルエット。
- 大量の魚体が回転した際に光が揃って変化する表現。
- 初期段階の複雑な海底・珊瑚・捕食者は不要。
- 障害物はリアルな岩より先に**明確な輪郭の抽象球体**を採用し、回避挙動を観察しやすくする。

### 9.2 変化を視認させる工夫

- 触れた直後に、局所的な方向転換が連鎖すること。
- 群れの密度変化が背景から識別できること。
- 画面外からの新しい群れが「現れた」と判別できること。
- 球体の前後で「分岐→迂回→再集合」が視認できること。

### 9.3 音

標準は控えめな環境音。タッチ・合流に過剰な電子効果音は付けない。設定からミュート可能。

| 3D | Three.js / WebGL |

### 10.2 モジュール

```text
src/
 ├─ app/                 # 初期化・モード遷移・保存
 ├─ input/               # タッチ、ピンチ、障害物編集
 ├─ simulation/
 │   ├─ FlockEngine      # 個体位置/速度更新
 │   ├─ SpatialHashGrid  # 近隣検索
 │   ├─ NeighborRules    # 分離・整列・結合
 │   ├─ WanderField      # 自律移動・環境流
 │   ├─ TouchRepulsion   # 指への反応
 │   ├─ ObstacleAvoid    # 予測回避
 │   ├─ GrowthManager    # 小集団の合流
 │   └─ GroupAnalyzer    # 分裂・密度・秩序の測定
 ├─ rendering/           # 魚モデル・インスタンス描画
 ├─ camera/              # 自動追従・ズーム
 ├─ ui/                  # モード切替・数値表示
 └─ debug/               # パラメータ調整・可視化
```

### 10.3 更新順序

1. 入力状態を取得し、忌避体積・障害物操作を更新。
2. 自律環境フィールドと成長管理を更新。
3. 空間ハッシュを構築／更新。
4. 各個体の近傍を取得。
5. 分離・整列・結合を計算。
6. 指・障害物・境界への回避を計算。
7. 速度／旋回角速度を制限して位置を積分。
8. 個体の反応状態を減衰。
9. 群れの分布・密度を分析してカメラ目標を更新。
10. 描画用インスタンス位置・回転を反映。

### 10.4 パフォーマンス

- 100～200匹で正しく動く試作を先に完成させる。
- 全組み合わせO(N²)ではなくSpatial Hash Gridで近傍探索。
- 物理更新：固定30Hzを初期基準とし、必要に応じ60Hzを評価。
- 描画：標準的な検証用スマートフォンで60fps目標、最低30fpsを目安。
- GPUインスタンシングでドローコールを抑える。
- 画質設定：自動／高／省電力。
- 演算時間・描画時間を測定し、**個体数だけでなく相互作用密度も負荷要因**として評価。
- 高負荷時は画質・影・粒子数を先に下げる。最大個体数を下げる場合も既存個体の突然の大量消滅を避ける。
- 複数の障害物・長押し・回転操作が重なってもNaN・無限速度を出さない。

### 10.5 開発者用の観察指標

- **偏極度 P（0～1）**：進行方向の揃い具合。`P = |Σ normalize(v_i)| / N`。
- 最近接距離：過密・めり込みの確認。
- 群れの半径・体積相当指標：広がりの確認。
- 連結成分数：近傍グラフから分裂・再集合を把握。
- 忌避の波及時間：直接触れた個体と後続個体の反応時間差。
- 障害物接触・侵入回数：回避失敗の監視。
- CPU更新時間、描画FPS、ドローコール。

偏極度が低いだけで分裂しているとは限らないため、連結成分数・空間密度を併用する。

### 10.6 再現性

デバッグ用に乱数シード固定機能を設ける。通常画面には表示しない。特定の群れ形成・障害物迂回失敗を同じ初期条件で再現できるようにする。

## 11. 開発計画

### Phase 0：最小動作確認

**内容：** 簡易魚モデル、30～100匹、3D空間で自律的に旋回、パラメータ可視化。

**合格条件：** 操作なしでも群れが持続し、画面外へ消失せず、個体が永続的に重なり続けない。

### Phase 1：触れると避ける（最重要）

**内容：** Vicsek/Boids/Couzin系の局所ルール、Pointer Events、タッチ忌避、反応の時間差、100～200匹。

**合格条件：** タッチ位置の周辺だけが先に反応し、その変化が群れの後方へ自然に広がる。

### Phase 2：障害物

**内容：** 球体の設置・移動・サイズ変更・削除、予測回避、2～5個配置。

**合格条件：** 障害物周辺で自然に避け、必要に応じて群れが分かれ、通過後に再集合する。衝突や振動が目立たない。

### Phase 3：仲間の増加と描画品質

**内容：** 小群合流、12→約500匹、カメラ自動追従、魚体反射、水中表現、端末性能対応。

**合格条件：** 合流する過程を視認でき、画質と動作が安定する。

### Phase 4：鳥モード・追加障害物

**内容：** 鳥モデル、羽ばたき、鳥専用挙動、壁・柱・トンネルなど。

**合格条件：** イワシと明確に異なる群れの運動が成立する。

### Phase 5：観察／共有機能

**候補：** 録画、スローモーション、時間停止、パラメータのプリセット、分裂数表示、比較モード。

## 13. 実装上のリスクと対策

| リスク | 原因 | 対策 |
|---|---|---|
| 群れが散り続ける | 結合が弱い、ノイズが強すぎる | 距離帯の調整、局所結合の強化 |
| 団子状に固まり動かない | 結合過多・分離不足 | 分離優先度、最低速度の調整 |
| 全体が一斉に逃げる | グローバル忌避が強すぎる | 指の影響を局所化し、近傍を介して伝播 |
| 球体の前で振動する | 後手の反発、回避方向の頻繁な反転 | 予測回避、側方経路の一定時間保持 |
| 分裂したまま戻らない | 長距離の相互作用不足 | 局所結合調整、孤立個体の弱い再合流補助 |
| タッチ位置と反応位置がずれる | 2D-3D座標変換の不整合 | カメラレイと基準面の定義を固定し検証 |
| 操作が煩雑になる | 忌避/設置/カメラ操作の競合 | モードを明示し、初期は1本指操作を単一目的に限定 |
| 500匹で重くなる | 近隣探索・描画負荷 | 空間分割、インスタンシング、段階的な品質調整 |
| 生き物に見えない | 全個体が同速度・同位相 | 個体差、旋回制限、モデル姿勢と泳動アニメーション |

## 14. 決定事項と保留事項

### 14.1 本版での決定

- 標準は**自律運動**。指でリーダーを操る方式は採用しない。
- 指は**忌避刺激**として機能する。
- ユーザーが**障害物を設置・移動・削除**できる。
- 初期開発はイワシ優先、3D、スマホWeb。
- Vicsek型整列とBoids分離/結合、距離別優先順位を組み合わせる。
- 仲間は画面外から自然に合流して増える。
- まず100～200匹で動作と楽しさを確認し、その後500匹を目指す。

### 14.2 試作後に決定

- 指への最適な忌避半径・減衰時間・反応感度。
- 自律遊泳の速度と曲率、群れの自然な回転・渦の発生条件。
- カメラのズーム速度と障害物の見失い防止。
- 障害物の適切な最大個数とサイズレンジ。
- 画面上の2D接触に対して3D深度をどこまで反応対象にするか。
- 鳥モードに適した独立パラメータと羽ばたきモデル。

## 16. 最初に制作するプロトタイプの定義

**プロトタイプ名：FLOCK v0.1 – TOUCH & AVOID**

- イワシ100匹、シンプルな魚型メッシュ。
- 何も触れなくても自律的に泳ぐ。
- タップ・長押し・ドラッグで自然に逃げる。
- 球体障害物を1個だけ設置して移動できる。
- 観察モードと接触モードを切り替えられる。
- デバッグUIで整列・分離・結合・忌避の係数を調整できる。
- 速度・個体間距離・FPS・偏極度が確認できる。
- 成長演出と鳥モードは、基本挙動の評価完了まで実装しない。

**最優先の合格基準：** まず単純な見た目で、魚群が**自律的にまとまり、触ると局所的に割れ、障害物を回避したあと自然に再集合する**ことを確認する。
