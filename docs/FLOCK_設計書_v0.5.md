### v0.4 からの主な変更点（v0.5）

1. **ムクドリモード（§16）：** 設定の「生きもの」でイワシとムクドリを切り替える。夕暮れの駅前から、ムクドリの大群（マーミュレーション）を見上げる。
2. **タッチはハヤブサ：** タップでハヤブサが急降下し、なぞると指を追って群れを追い回す。群れに黒い波が走る。
3. **時間の流れ：** 成長モードのときだけ、夕焼けの中で小群が合流し、日没後に街路樹のねぐらへ降りて、夕方からやり直す。
4. **群れの計算：** ムクドリは「近い順に7羽」を見る方式（位相的な近傍）にする。パラメータはイワシと別に持つ。

### v0.3 からの主な変更点（v0.4）

1. **海底：** 餌は海底から50 cm以上の高さにまく。魚は海底に近づくと上向きに舵を切り、海底より下へは出ない（実装 v0.13）。
2. **画質と最大数：** 画質を「自動／大群／省電力」の3つにした（「高」は自動に統合）。最大数は省電力250・自動500〜1000・大群2000匹（実装 v0.14）。
3. **裏モード：** 設定画面の版数の行を5回タップすると表示。開発者表示・開始時の匹数・更新履歴をまとめた（実装 v0.14）。

### v0.2 からの主な変更点（v0.3）

1. **障害物：** 半透明の球をやめ、**浮き玉（係留ブイ）**と**岩の柱**の2種類にした。どちらも海底を基準に置き、ドラッグで水平に動かして、高さはスライダーで決める。
2. **餌やり：** 新しく追加した。「触れる」モードの中で、道具を「手」から「餌」に切り替えて使う。
3. **観察モード：** タップで魚に色を付け、ドラッグで視点を回せるようにした。
4. **2本指の操作：** すべてのモードで、2本指で拡大縮小と視点回転ができる。指1本目は0.12秒待ってから操作を始め、2本指の拡大縮小を誤って「触る・餌・障害物」の操作にしない。
5. **目印：** 海底と1mマス目、岩、群れが泳ぐ範囲の枠、スケールバーを、設定から出し入れできるようにした。
6. **サウンド：** 水の環境音、タッチ音（水滴）、群れが動く水音、餌の音を付けた。v0.2 の「タッチに効果音を付けない」方針は変更した。
7. **技術構成：** TypeScript＋Vite をやめ、素のJavaScriptで書いて1つのHTMLにまとめる構成に変更した（§11.1）。

## 1. 企画概要

### 1.1 コンセプト（v0.2 から変更なし）

イワシの魚群が自律的に移動・旋回・集合・分裂する様子を眺めながら、指で触れたり、障害物を置いたり、餌をまいたりして群れの反応を楽しむインタラクティブ・シミュレータ。

**プレイヤーは「リーダー」ではなく「環境の一部」になる。** 群れは常に自律的に動き、何もしなくても成立する。

### 1.2 体験の柱

| 柱 | 内容 | 主な機能 |
|---|---|---|
| 眺める | 指示なしで群れが自然に動き続ける | 自律群泳、カメラ自動追従、観察モード |
| 驚かせる | 触れた場所の個体が逃げ、影響が隣へ伝わる | 触れる（手） |
| 実験する | 障害物の種類・位置・大きさを変えて反応を比べる | 浮き玉、岩の柱 |
| 育てる | 周辺の小集団が合流し、群れが大きくなる | 成長モード（設定で切替） |
| 群がらせる | 水族館の餌やりのように、餌に群がる様子を見る | 触れる（餌） |
| 見入る | 群れの分裂・回転・再集合を、好きな角度から見る | 視点回転、色付け、目印 |

### 1.3 製品の位置づけ

- 勝敗や得点ではなく、**自然現象の観察と、操作による発見**を優先する。
- 登録やサーバー通信は不要。開けばすぐ遊べる1枚のWebページにする。
- **画面の個体は人工的なモデルで、実際の魚の生態を厳密に再現したものではない**（設定画面にも明記している）。

### 1.4 実装の状況

| 区分 | 項目 | 状況 |
|---|---|---|
| MVP必須 | イワシ、自律群泳、触れると逃げる、障害物の配置・移動・削除、迂回と再集合、仲間の合流、個体数の表示 | 実装済み |
| 追加（v0.3で仕様化） | 餌やり、浮き玉・岩の柱、目印、色付け、視点回転、サウンド、一時停止、横画面、開発者表示 | 実装済み |
| 仕様化（v0.5） | ムクドリモード（§16） | 未実装 |
| 後続 | 壁・トンネルなど追加の形、録画・共有、スローモーション、パラメータのプリセット | 未着手 |

**モード別パネル**

- **触れる：** 「手／餌」の切替ボタン（小さな1行）
- **障害物：**

- **観察：** 色付けパネル（色見本5色、「ランダムに3匹」「すべて外す」）

### 3.2 横画面（横長で、画面の高さが600px以下のとき）

- **右側：** 上に一時停止・設定ボタン、下にモード切替を縦に並べる。
- **左側：** 下にモード別パネルとヒント、上にスケールバー。
- 画面の中央は群れのために空けておく。

### 3.3 共通の表示

| 要素 | 仕様 |

| ひとことヒント | モードや道具を切り替えたときに5秒だけ表示。画面に触れるとすぐ消える |

## 4. 操作仕様

### 4.1 モードと道具

| モード | 1本指タップ | 1本指ドラッグ | 補足 |
|---|---|---|---|
| **触れる：手**（標準） | 触れた所に短い刺激を与える | 指の軌跡に沿って刺激が続く | 群れの進路は指示しない |
| **触れる：餌** | タップした所に餌を28粒まく | 34pxごとに8粒ずつ、なぞった線に沿ってまく | 餌は最大260粒まで |
| **障害物** | 空いている場所に置く／置いてあるものを選ぶ | 選んだものを水平に動かす | 最大5個 |
| **観察** | 指の近く（34px以内）の魚に色を付ける。もう一度タップで外す | 視点を回す | 群れには影響しない |

### 4.2 カメラ

| 操作 | 内容 |
|---|---|
| 自動追従 | 群れの中心をゆっくり追い、群れの広がりに合わせて距離を変える。わずかに揺れて立体感を出す |
| 2本指（全モード） | 指の間隔を変えると拡大縮小（0.45〜2.4倍）、2本そろえて動かすと視点回転 |
| 1本指（観察モードのみ） | ドラッグで視点回転 |
| パソコン | ホイールで拡大縮小、右ボタンのドラッグで視点回転 |
| 制限 | 見下ろす角度は −0.2〜1.3 rad。カメラは海底より下に潜らない |
| 視点を戻す | 設定から。回転と拡大縮小を初期値に戻す |

### 4.3 2本指の誤操作を防ぐ（v0.12）

- **待ち時間：** 指が1本触れたら **0.12秒** 待つ。その間に2本目が来たら、拡大縮小・回転として扱い、何も起こさない。
- **すぐ操作を始める場合：** 待っている間に、指を離した（タップ）、または12px以上動いた（ドラッグ）ときは、待たずに通常の操作を実行する。
- **取り消し：** 操作を始めてから **0.6秒以内** に2本目の指が来たら、その間に置いた障害物とまいた餌を取り消す。
- **マウス：** 2本指の操作がないため、待ち時間を入れない。

### 4.4 短いタップの取りこぼし防止（v0.7）

指を一瞬で離しても、刺激は最低 **0.15秒** 続ける。物理の計算は1秒に30回なので、これより短い指の接触は計算に一度も届かず、無視されていた。

### 4.5 キーボード

| キー | 動作 |
|---|---|
| Space | 一時停止／再開 |
| 1・2・3 | 触れる・障害物・観察に切替 |
| Esc | 設定を閉じる |

### 4.6 一時停止

- 群れの計算、カメラの揺れ、光の揺らめきが止まる。
- 止めている間も、障害物の配置・移動と、拡大縮小・視点回転はできる。

## 5. 集団行動モデル

### 5.1 採用方針（v0.2 から変更なし）

次を組み合わせる。

- Vicsek型の局所整列（周りの向きにそろえる）
- Boids型の分離・結合（近すぎたら離れ、離れすぎたら寄る）
- Couzin型の距離別優先順位（衝突の危険が高いときは分離を優先）
- 環境からの忌避（指・障害物・世界の境界）

整列の仕組みは1つだけにする（Boidsの整列とVicsekの整列を二重に足さない）。

### 5.2 個体の状態

各個体は次の値を持つ。

- 位置・速度（3D）
- 尾びれの位相
- 反応の個体差（0.75〜1.25）、速さの個体差（0.9〜1.1）、大きさ（0.88〜1.12）
- `stress`：指への驚き（0〜1）
- `feed`：餌への興奮（0〜1）
- 群れID（0＝本体。正の値＝合流途中の小集団）

### 5.3 近傍と合成

| 区分 | 半径 | 重み（既定） |
|---|---|---|
| 分離 | 0.6単位（約30 cm） | 2.6（驚いているほど半径と重みが大きくなる） |
| 整列 | 1.4単位（約70 cm） | 1.6 |
| 結合 | 2.8単位（約1.4 m） | 0.6 |

**近傍の数え方**
- 真後ろ（cos < −0.55 の方向）は死角とし、整列と結合には使わない。
- 近傍は最大28匹まで数える。

**整列の計算**
- 近傍の平均の向きにノイズ（0.16）を加え、その向きへ舵を切る。
- 近傍の向きがばらばら（平均の向きの強さが0.12以下）のときは整列を使わない。

**重みの切り替え（Couzin型の優先順位）**
- 分離・指・障害物の緊急度が高いほど、整列と結合を弱める。
- 餌に興奮しているほど、整列（最大65%）と結合（最大60%）を弱める（§8）。

**その他の力**
- 環境の流れ：ゆっくり変化する弱い3Dの流れ（重み0.3）
- ソフト境界：重み1.6
- 再合流の補助：重み1.0。合流途中の小集団と、1.5秒以上ひとりになった個体だけに働く

### 5.4 運動の制限

| 項目 | 平常時 | 驚いたとき |
|---|---|---|
| 速さ | 巡航 2.0単位/秒（約1 m/秒）、最低 1.1 | 最大 6.2 |
| 加速度 | 4 | 22 |
| 旋回の速さ | 2.6 rad/秒 | 8.0 rad/秒 |

- 上下を向ける角度に上限がある（進行方向の上下成分 |dir.y| ≤ 0.62）。魚は真上・真下へは泳がない。
- 真後ろへの瞬間的な反転は禁止。個体ごとに決まった好みの側へ回り込む。
- 計算が壊れても破綻しないよう、NaN（数値でない値）が出た個体は、群れの中心付近に置き直す。
- 海底から0.8単位以内に近づくと上向きの力が働き、海底より下（体の半径0.1単位まで）へは出ない（v0.4）。

### 5.5 指への反応

**刺激の位置と形**
- タッチした画面上の点から視線を伸ばし、群れの中心を通ってカメラに正対する面との交点に刺激を置く。
- 刺激は、前回の位置から今回の位置までの線分（カプセル形）にする。指を速く動かしても、途中の魚をすり抜けない。
- 半径 R ＝ 画面の短い辺の15% × 指の半径の倍率。長押しすると0.6秒かけて0.7Rから1.0Rへ広がる。
- 奥行き方向の厚みは 1.6R。

**刺激の強さと時間**
- 指が触れている間は素早く強まる。
- 指を離すと、時定数0.17秒で弱まる（約0.2〜0.6秒で消える）。

**伝播（stress）**
- 直接触れた個体は、反応の個体差に応じて stress が上がる。
- 周りの仲間の最大 stress × 0.8 に向かって、自分の stress も上がる（速さ 3/秒）。
- stress は 0.85/秒 で減っていく。

**表現**
- 驚いた魚や急旋回した魚の体側が、わずかに明るく光る（最大30%）。
- 群れの近くに触れたときだけ、群れが動く水音を鳴らす（§10）。

### 5.6 成長（小集団の合流）

- 合流の計画：0秒で12匹 → 30秒で30匹 → 90秒で90匹 → 180秒で220匹 → 270秒で500匹 → 420秒で1000匹 → 600秒で2000匹。実際の上限は画質の最大数で止まる。
- 小集団（4〜46匹）は、5〜10秒ごとに画面の外（左右、または奥の霧の中）から現れる。
- 合流の判定：本体の近くで1秒間、一緒に行動したら合流済みとし、そのときに個体数の表示を増やす。
- 個体を消すことはない。画質の自動調整で最大数を下げるときも、すでにいる個体は消さない。

## 6. 障害物（v0.9〜）

### 6.1 種類

| 種類 | 見た目 | 回避の判定 |
|---|---|---|
| **浮き玉**（係留ブイ） | 縄の網をかけた緑色のガラス玉。細いロープで海底の重りにつながっている | 玉は球として、ロープは半径0.03の縦のカプセルとして扱う（余裕0.1） |
| **岩の柱** | 海底から立つ岩の柱。根元は太く、頂部は丸い。岩と同じ質感 | 海底から「高さ − 0.3×半径」までの縦のカプセルとして扱う |

浮き玉の網と光沢は、玉の丸さを伝えるためのもの。ロープと重りは、水平の位置と高さを伝えるためのもの。

### 6.2 データ

```js
{ id, kind: 'buoy' | 'pillar', x, z, radius, height,   // height は海底からの高さ
  tx, tz, targetRadius, targetHeight,                  // 指で動かすときの目標値（実際の値はゆっくり追いつく）
  y, y0, y1, vx, vy, vz, enabled }                     // y は浮き玉の中心、y0〜y1 は柱・ロープの範囲
```

### 6.3 操作

**置く**
- 空いている場所をタップすると、視線と「群れの高さの水平面」の交点に置く。群れの高さは、海底+2〜+13単位の範囲に収める。
- 高さの初期値：
  - 浮き玉：群れの高さ
  - 柱：群れの高さより2.5単位（1.25 m）高い
- 種類は「次に置く種類」として選ぶ。置いてあるものの種類は変えない。

**動かす**
- 掴んだ高さの水平面上で動かす。視点を回しても動き方は変わらない。
- 群れが泳ぐ範囲（水平方向の85%）の内側に留める。
- 動く速さの上限は8単位/秒。

**大きさを変える**
- サイズは半径0.5〜2.5単位、高さは2〜15単位（1〜7.5 m。画面には m で表示）。
- 半径は2.5単位/秒、高さは5単位/秒の速さで目標値に追いつく。

**その他**
- 置けるのは最大5個。上限に達したらトーストで知らせる。
- 画面の端（左右8%・上10%・下14%）には置けない。
- 選んでいる障害物は、足元の海底に破線のリングを表示する。浮き玉には、さらに玉の周りに破線のリングと4つの点も付ける。
- 海底を非表示にしているときも、足元に砂地と影を表示する。

### 6.4 回避の計算（v0.2 §6.2 の方針どおり）

1. **形を広げて扱う：** 障害物の半径に、余裕0.38と魚体の半径0.1を足した「拡張半径」で判定する。柱とロープは、魚の高さに一番近い軸上の点を中心として扱う。
2. **近づきすぎたとき：** 最短の方向へ外向きに押し出す。
3. **ぶつかる前に避ける：** 障害物との相対速度で、1.15秒先までの進路を予測する。進路が拡張半径に入るなら、横へ外周を回る方向へ舵を切る。真正面のときは、個体ごとの好みの側へ回る。
4. **最後の保険：** それでもめり込んだら、位置を少しずつ押し戻す。めり込んだ回数は開発者表示に出る。

### 6.5 岩（固定の目印）

- 6個の大きな岩と、それぞれの周りに2〜3個の小石を、海底に固定で置く。
- 魚は、半径0.45以上の岩・小石をよける。
- 見た目：
  - ノイズを重ねた凹凸に、平らな割れ面を混ぜた形
  - くぼみは暗く、細かい斑点があり、上面にはまだらに藻が付く
  - 海底に接地の影を落とす
  - 上を向いた面に、水面からの光の揺らめきが当たる

## 7. 観察モード・色付け（v0.3〜）

- 色は5色（コーラル、イエロー、ピンク、ライム、バイオレット）。最大8匹まで付けられる。
- 付けるたびに次の色へ自動で切り替わる。色見本から選ぶこともできる。
- 「ランダムに3匹」は、本体に合流済みの魚から選ぶ。「すべて外す」もある。
- 色の付いた魚は、体の色をその色に変え、さらに少し発色させて、群れの中でも見失わないようにする。
- 群れを最初からやり直すと、色はすべて外れる。

## 8. 餌やり（v0.10〜）

**目標：** 水族館の餌やりのように、餌の周りに魚が群がって奪い合い、食べ終わると元の群泳に戻る様子を再現する。

### 8.1 餌粒

- 1回のタップで28粒（広がり0.8単位）、なぞると8粒ずつ（広がり0.4単位）まく。全体の上限は260粒。
- まく位置は、指の視線と「群れの中心を通りカメラに正対する面」の交点。その点が海底から1単位（50 cm）より低いときは、視線上で海底から1単位の高さの点に置き直し、群れが泳ぐ範囲の内側に留める（v0.4）。
- まいた直後は外側へぱっと広がり、その後は秒速0.2単位（約10 cm）で沈みながら、わずかに揺れて漂う。
- 海底に落ちた粒は、6秒後に消える。
- 見た目はオレンジ色の点。サイズ0.14単位で、遠くは霧に溶ける。

### 8.2 魚の反応

| 要素 | 仕様 |
|---|---|
| 見つける | 9単位（4.5 m）以内で一番近い粒へ向かう |
| 食べる | 0.2単位以内に届いたら、計算1回ごとに25%の確率で食べる。毎回は食べられないので、餌の周りでしばらく渦を巻く |
| 興奮の目標値 | 近くに餌があれば0.65〜1.0。見えていなくても、周りの仲間の興奮の最大値×0.8 |
| 興奮の伝わり方 | 目標値に向かって3/秒で上がる。離れた仲間へも、近い順に伝わる |
| 興奮が冷める | 0.32/秒で減る |
| 餌が見えない魚 | 興奮が0.15より大きければ、まかれた餌全体の中心へ向かう |
| 興奮したときの動き | 整列・結合を弱める。餌へ向かう力（3.2 ×（0.35+0.65×興奮））と、小刻みな方向転換を加える。速さは驚いたときの35%まで、旋回は驚いたときの60%まで上げる |
| 指との関係 | 指で驚かされている間は、餌へ向かう力を弱める |
| 表現 | 興奮している魚もわずかに光る。餌をまくと「ぽつぽつ」という小さな水音を鳴らす |

**テストでの結果（100匹、28粒）：** 約2〜3秒で食べ切り、その間は群れの向きのそろい具合（偏極度）が0.3〜0.7まで崩れた。15秒後には元の群泳に戻った。

## 10. 画面デザイン・サウンド

### 10.1 見た目

**魚**
- 細身の紡錘形：体の高さは体長の約19%で、吻をやや尖らせる。
- 配色：背は青緑、その下に青紫の光沢帯、体側は銀、腹は白。
- 尾びれ：二又に分かれた形。上下の開きは体の高さとほぼ同じで、長さは全長の約15%。
- **背びれ・胸びれは付けない**（ユーザーの判断。§13）。
- 動き：尾は頂点シェーダーで左右に振る。振れ幅は、驚いているときや速いときほど大きい。旋回の方向へ体を傾ける。

**水中**
- 背景：上方は明るいターコイズ、下方は深い紺。
- 水面から差し込む光の筋がゆっくり揺らぐ。
- 細かい漂流物（マリンスノー）が漂い、霧で奥行きを出す。
- 画面の周辺を少し暗くする（ビネット）。

**UI**
- 暗い水中の雰囲気に合わせた、ダーク固定のテーマ。
- フォント：ロゴは Unbounded、本文は Zen Kaku Gothic New、数字は IBM Plex Mono（いずれも Google Fonts）。

### 10.2 サウンド（すべて Web Audio で合成。音声ファイルは使わない）

| 音 | 内容 | 条件 |
|---|---|---|
| 環境音 | 低いうねり（300 Hz以下）＋寄せては返す水の揺らぎ（650 Hz付近。周期の違う2つのゆらぎ）＋1.8〜6.3秒ごとに立ちのぼる泡 | 設定「環境音」がオン |
| タッチ音（水滴） | 450〜1100 Hzの間で毎回ランダムな高さから上がる短い音（なぞると小さく続けて鳴る） | 設定「タッチ音」がオン |
| 群れが動く水音 | 低域の雑音を、220 → 820 → 260 Hz の帯域でゆっくり（約1秒）変化させる。小さな泡の音を1〜3個添える | タッチ音がオンで、触れた所の近くに3匹以上いるとき |
| 餌の音 | 1300〜2600 Hzの小さな泡を2〜7回 | タッチ音がオン |

- 全体の音は、コンプレッサー（音量の急な跳ね上がりを抑える処理）と、2.2秒の水中らしい残響を通す。
- 音量はスライダー（0〜100）で決め、実際の大きさはスライダー値の2乗に比例させる。
- ブラウザの決まりにより、**最初に画面へ触れたときに鳴り始める**。
- アプリが画面から隠れているときは音を止める。
- 音の大きさの目安（ブラウザでの計測）：環境音の実効値は −34 dBFS 前後で、タッチ音のピークは環境音のピークより約4〜5 dB大きい。

### 11.1 構成（v0.2 から変更）

| 3D | Three.js | Three.js **r128**（cdnjs から読み込む） | |

| 描画 | InstancedMesh | InstancedMesh に加え、頂点シェーダーで尾を振る | |
| 入力 | Pointer Events | Pointer Events（2本指の判定付き） | |
| 保存 | localStorage | `flock.settings`（設定）と `flock.guideSeen`（初回ガイドを見たか） | |

### 11.2 ファイル

```text
src/engine.js   群れエンジン（描画なし）：近傍探索・分離/整列/結合・指・障害物・岩・餌・成長・観察指標
src/app.js      描画・入力・カメラ・UI・サウンド
src/shell.html  画面の部品（HTML/CSS）と更新履歴
tools/build.py  1つのHTMLにまとめて index.html と releases/flock_v{版数}.html を書き出す
```

### 11.3 1回の更新の順序

1. 指の状態から、刺激（カプセル）を更新する（app）
2. 障害物の位置・大きさ・高さを、目標値へ近づける
3. 成長（小集団の出現）と、餌粒の移動・削除
4. 回避に使う形（球・縦のカプセル）を、障害物と岩から並べる
5. 近傍探索用の空間ハッシュ（空間を格子に分けて近くの個体を素早く探す仕組み）を作る
6. 各個体について：近傍の集計 → 分離・整列・結合 → 再合流の補助 → 指 → 障害物 → 環境の流れ → ソフト境界 → 餌 → 合成 → 旋回・上下角の制限 → 速さ → stress
7. 位置を進め、めり込んでいたら押し戻す。NaN が出ていたら置き直す。合流を判定する
8. 群れの中心と広がりを更新する（カメラの目標になる）
9. 描画：前回と今回の位置の間を補間し、向き・傾き・尾の振り・光り・色付けを反映する

### 11.4 性能

- **計算時間（PC、Node.js で計測）：** 500匹で約1.6 ms、1000匹で約2.4 ms、2000匹で約5 ms（匹数にほぼ比例）。スマホの実機では、まだ計測していない（PCの3〜5倍と見込む）。
- **画質「自動」：** 最大数は500匹から始める。3秒ごとに次を判定する（一時停止中は判定しない）。
  1. FPSが42を下回ったら、描画の解像度を0.5ずつ下げる（最低1倍）。
  2. FPSが30を下回るか、計算に12 msを超えたら、最大数を今の数で止める（以後、上げない）。
  3. FPSが50以上・計算5 ms未満で、個体数が最大数に届いていたら、最大数を250匹ずつ上げる（1000匹まで）。
- **画質「大群」：** 最大2000匹。解像度1倍、アンチエイリアスなし（次に開いたときから）、マリンスノー・海底と岩の光の揺らめき・驚いたときの光りを省く。重いときの判定は「自動」の1・2と同じ。
- **画質「省電力」：** 解像度1倍、アンチエイリアスなし、最大250匹。
- 画質を変えても、すでにいる個体は消さない。旧版の「高」の保存値は「自動」として読む。

### 11.5 裏モードと開発者表示

- **裏モード（v0.4）：** 設定画面の一番下にある版数の行を、2.5秒以内に5回タップすると表示する（表示したかどうかは保存）。「裏モードを閉じる」で隠す。
  - 開発者表示のスイッチ（下記）
  - 開始時の匹数：10〜画質の上限（省電力250・自動1000・大群2000）。「この数で始める」で群れを最初からやり直す。「既定に戻す」で、成長モードなら12匹、そうでなければ100匹に戻す。値は保存され、次に開いたときもその数で始まる。
  - 更新履歴：版ごとの要約（以前は設定画面に常に表示していた）

- **指標：** 個体数、FPS、計算時間、偏極度P（向きのそろい具合）、最近接距離（平均と最小）、群れの半径、連結成分の数（3匹以上のまとまりがいくつあるか）、平均速度、最大 stress、障害物へのめり込み回数、描画の解像度、乱数シード。
- **スライダー：** 分離・整列・結合・ノイズ・忌避・警戒伝達・障害物・指の半径・遊泳速度。「係数の説明を表示」で、各スライダーの下に意味を出せる。「係数を既定値に戻す」ボタンもある。
- **その他：** 刺激の範囲と障害物の拡張半径を、ワイヤーフレームで表示できる。乱数シードを固定して、最初からやり直せる。
- **テスト用の入口：** `FLOCK.debugEngine`、`FLOCK.debugAudio()`、`FLOCK.debugView(yaw, pitch, zoom)`（自動テストで使う）。

## 13. 決定事項と却下事項（ユーザー判断の記録）

### 13.1 決定（v0.2 からの引き継ぎを含む）

- 群れは常に自律で動く。指でリーダーを操る方式は採らない。
- 指は「驚かせる刺激」として働く。
- 障害物は「浮き玉」と「岩の柱」。
- 餌やりは「触れる」モードの道具として扱う（モードは増やさない）。
- 視点回転は、観察モードの1本指と、全モードの2本指で行う。
- UIは最小限にする。中央は群れのために空ける。

### 13.2 却下（再提案しない）

| 却下したもの | 理由（ユーザーの言葉の要約） | 版 |
|---|---|---|
| 背びれ・胸びれ | 目立つとノイズ。主役は胴体と尾びれと魚のフォルム | v0.3で削除 |
| 大きすぎる尾びれ | 実物の写真に合わせて小さく | v0.4で縮小 |
| 「新しい仲間が近づいています」のトースト | おしゃれ感を損なう。「+N 接近中」だけでよい | v0.3で削除 |
| 水琴窟風のタッチ音 | イメージと全然違った | v0.7で削除 |
| タッチ音の種類選択 | オン／オフだけでよい | v0.7で削除 |
| 帯域を絞った「ザッ」という水音 | 不自然 | v0.10で変更 |
| 大きな障害物パネル | 邪魔 | v0.10で小型化 |
| 半透明の球の障害物 | 位置が分かりにくく、球に見えない | v0.9で置換 |
| 画面左右の大きな見出しや大きな個体数（試作Bの案） | UIは最小限に | 採用せず |

### 13.3 試作B（別のAIの試作）から取り入れたもの

一時停止、キーボード操作、モード別のヒント、驚いた個体の光り、光の筋とビネット、選んだ障害物の破線リング、障害物を範囲内に留める、遊泳速度のスライダー。

- ムクドリモードのパラメータの最終値（§16.13）

## 16. ムクドリモード（v0.5 で仕様化・未実装）

> 数値はすべて**試作の初期値**。スマホ実機で見ながら調整し、決まった値は次の版の設計書に書く。
> 項目の後ろの【決定】は、ユーザーが壁打ちで選んだもの。【案】は開発側の提案で、試作を見てから変えてよいもの。

### 16.1 コンセプト

夕暮れの駅前に立ち、ムクドリの大群が空でうねる様子（マーミュレーション）を見上げる。

- 群れは常に自律で動く。プレイヤーは「環境の一部」（§1.1 と同じ）。
- 見どころは、群れ全体の形が液体のように伸び縮みし、濃淡の波が走ること。1羽1羽ではなく**群れの形**を主役にする。
- 舞台は日本の駅前。ねぐらは駅前の街路樹【決定】。

### 16.2 切り替え【決定】

- 設定 ⚙ に「生きもの：イワシ／ムクドリ」を足す。選んだ値は `flock.settings` に `species: 'sardine' | 'starling'` として保存する。
- 切り替えると、群れを最初からやり直す（開始時の匹数・成長モードの設定はそのまま使う）。
- 画質（自動／大群／省電力）、音量、成長モード、裏モードの設定は、イワシと共通にする。
- 表示の単位は「匹」から「羽」に変える。

### 16.4 集団行動モデル（ムクドリ用のパラメータ）

イワシと同じ `FlockEngine` を使い、**種類ごとのパラメータの組**を切り替える（v0.2 §8 の「魚のパラメータを流用しない」を守る）。

**近傍の取り方：近い順に7羽【案】**
- 整列と結合は、距離ではなく**近い順に7羽**を相手にする（参考文献4）。群れが伸びて間隔が広がっても、まとまりが保たれる。
- 探す範囲の上限は 8 m。7羽に満たないときは、見つかった分だけ使う。
- 分離（ぶつからないための反発）は、イワシと同じく距離で決める（半径 0.8 m）。
- 死角は真後ろ（cos < −0.6）。

**飛び方【案】**

| 項目 | 平常時 | ハヤブサから逃げるとき |
|---|---|---|
| 速さ | 巡航 10 m/秒、最低 7 m/秒（鳥は止まれない） | 最大 18 m/秒 |
| 旋回の速さ | 1.6 rad/秒 | 5.0 rad/秒 |
| 上下の向き（進行方向の上下成分） | 0.45 以内 | 0.7 以内 |

- **傾けて曲がる：** 旋回の速さに比例して体を傾ける（最大60°）。傾くと翼の面が観る人の方を向き、群れの中に**濃い帯と薄い帯の波**ができる。この濃淡がマーミュレーションの見どころなので、色や明るさで別に作らず、形の向きで自然に出す。
- **平たい群れ：** 上下方向の速度を弱める力を入れ、群れを横に広い板のような形に保つ（参考文献6）。
- **ねぐらの引力：** 群れが範囲の中心（ねぐらの上空）から離れすぎると、弱く引き戻す。これがあると群れが同じ空でうねり続ける。
- 環境の流れ（ゆっくり変わる風）は、イワシより強めにして、ハヤブサがいないときも形が変わり続けるようにする。

### 16.5 ハヤブサ（触れる）【決定】

| 操作 | 動き |
|---|---|
| タップ | 画面の外（観る人の背後の上空）から、ハヤブサがタップした場所へ**急降下**し、群れを突き抜けて反対側へ飛び去る |
| なぞる | ハヤブサが**指を追って**飛び、群れを追い回す。指を離すと、そのまま飛び去る |

- 空にいるハヤブサは**常に1羽**。飛んでいる途中で新しくタップ・なぞると、今のハヤブサが向きを変える。
- 狙う位置：タップした画面上の点から視線を伸ばし、群れの中心を通って観る人に正対する面との交点（イワシの刺激と同じ考え方）。
- 速さ【案】：急降下は 35 m/秒、追いかけは 20 m/秒。旋回の速さに上限を付け、急に向きを変えない（ムクドリの方が小回りがきくので、かわされる）。
- **鳥は捕まえない【案】：** 群れが裂けて逃げる様子を見せるのが目的。羽数は減らさない。
- 2本指の誤操作対策（§4.3）は、イワシと同じく使う。

**群れの反応**
- ハヤブサの周り 12 m 以内の鳥は、ハヤブサから遠ざかる向きへ急旋回する（近いほど強い）。
- 驚き（stress）は「近い順の7羽」を通じて伝わる。イワシより速く伝え、**黒い帯の波が群れを一瞬で走る**ようにする（参考文献5。実物では秒速20〜40 m）。
- ハヤブサの通り道には、一時的に**穴（空洞）**があき、通り過ぎると閉じる。
- 群れが2つ以上に裂けても、時間がたつと再び1つにまとまる。

**見た目**
- ムクドリより一回り大きいシルエット。翼は細く尖った形で、急降下のときは翼をたたむ。
- 光る輪やマークなどの目印は付けない（UIは最小限）。

### 16.6 見た目

**ムクドリ【決定】**
- 羽ばたく小さなシルエット（胴体と左右の翼だけの簡単な形）。
- 羽ばたき（1秒に約12回を0.3〜0.8秒）と滑空（0.2〜0.5秒）を、個体ごとにずらして繰り返す。翼の動きは頂点シェーダーで作る。
- 色はほぼ黒。遠いほど空の色に溶ける（空気遠近法）。遠くの鳥は自然に点になるが、**見かけの大きさに下限**を付けて、点が消えないようにする。

**空【案】**
- 西の地平線の近くは橙、上へ行くほど桃色から深い青へ。沈んだ太陽の明るさが西の空に残る。
- 薄い雲の帯が2〜3本あり、夕日の色に染まる。
- 夜になると星がいくつか出る。

**駅前の街【決定】**
- 画面の下の方に、黒いシルエットで描く：駅舎、ビル、こんもりした街路樹（ねぐら）、電柱と電線、街灯。
- **灯り【決定】：** 空が暗くなるにつれて、ビルの窓と街灯がぽつぽつ点く。成長モードがオフのとき（夕焼けのまま）は、少しだけ点いている。
- 街は中央の空をふさがないよう、画面の下 25% 程度に収める。

**画質「大群」で省くもの【案】：** 雲の帯、星、窓の灯りの瞬き。解像度とアンチエイリアスはイワシと同じ扱い（§11.4）。

**UI：** イワシと同じダーク固定のテーマとフォントを使う。

### 16.7 時間の流れ（成長モードのときだけ）【決定】

成長モードがオフのときは、日没直後の夕焼けの空で、ずっと飛び続ける。

成長モードがオンのときの1回の流れ【案】（約7分半）：

| 時刻 | 空 | 群れ |
|---|---|---|
| 0:00 | 夕焼け | 12羽から始まる。地平線や街の向こうから、小さな群れが次々に合流する |
| 〜6:00 | 日没 → 薄暮。街の灯りが点き始める | 合流の計画：0秒で12羽 → 20秒で40羽 → 60秒で120羽 → 120秒で300羽 → 200秒で600羽 → 280秒で1000羽 → 360秒で2000羽（画質の最大数で止まる） |
| 6:00〜7:20 | 薄暗い | **ねぐら入り：** 群れの一部が渦を巻くように細い流れになって街路樹へ降りていき、最後の1羽まで続く。降りた鳥は木の中に入って見えなくなる |
| 7:20〜7:30 | 夜。窓と街灯だけが明るい | 空には何もいない（静かな数秒） |
| 7:30 | 空がゆっくり夕焼けに戻る | 12羽から、もう一度始まる |

- ねぐら入りの間に表示する羽数は「空にいる数」（降りるごとに減る）。§5.6 の「個体を消さない」の例外は、このねぐら入りだけ。
- ねぐら入りの途中でもハヤブサは使える。驚いた鳥はいったん舞い上がり、また降りる。
- 一時停止すると、空の時間も止まる。

### 16.8 サウンド【決定】

| 音 | 内容 | 条件 |
|---|---|---|
| 環境音 | 夕方の弱い風（低めの広い帯域の雑音を、ゆっくり強弱）＋遠くのムクドリの声（短い「キュルッ」「ジャー」に近い声を Web Audio で合成し、遠く小さく）。声の回数は空にいる羽数に合わせて増減 | 設定「環境音」がオン |
| タッチ音 | **鳴らさない**。ムクドリモードでは設定の「タッチ音」の行を出さない | |

- 羽音、電車や街の音は付けない【案】（「ザッ」に似た音になるのを避ける。§13.2）。
- 夜（ねぐら入りの後）は、鳥の声を止めて風だけにする。
- 音量・残響・鳴り始めの決まりはイワシと同じ（§10.2）。

### 16.9 カメラ

| 操作 | 内容 |
|---|---|
| 自動追従 | 立つ位置は固定。群れの中心へ、首を振るようにゆっくり向きを変える。群れの広がりに合わせて画角を変え、群れ全体が画面に入るようにする |
| 2本指（全モード） | 指の間隔で拡大縮小（画角を変える。0.5〜2倍）、2本そろえて動かすと見る向きを変える。手を離して3秒たつと自動追従に戻る |
| 1本指（観察モードのみ） | ドラッグで見る向きを変える |
| 制限 | 見上げる角度は 0〜80°。地面より下は向かない |
| 縦画面・横画面 | 縦画面では画角を広めにし、街を下に、空を大きく見せる |

### 16.10 技術設計

- **エンジン：** `new FlockEngine({ species: 'starling', ... })` で、ムクドリ用のパラメータの組（`SPECIES.starling`）を使う。イワシは `species` を省略したときの既定値で、今の動きを変えない。
  - 近傍の取り方 `neighbor: 'metric' | 'topo'` と、その数 `k: 7` を足す。空間ハッシュで近くを探し、距離の近い順に k 羽を選ぶ。
  - ハヤブサは `engine.predator = { x, y, z, vx, vy, vz, R }` で渡す（いないときは null）。動かすのは app の側で、エンジンは鳥の反応だけを計算する。
  - ねぐら入りは `engine.roost = { x, y, z, radius, active }` で渡す。木の中に入った鳥は `hidden` にして、計算から外す。
  - 描画（THREE や DOM）に依存させない決まり（CLAUDE.md）は守る。
- **描画：** 鳥は InstancedMesh（翼を頂点シェーダーで羽ばたかせる）。空・雲・星・街はシェーダーと簡単な板（ビルボード）で描き、画像ファイルは使わない。
- **ファイル：** `src/app.js` が大きくなりすぎる場合は、ムクドリの描画を `src/starling.js` に分け、`tools/build.py` で一緒に連結する。
- **開発者表示に足す指標：** 空にいる羽数、ハヤブサの状態、時間の流れの位置（例：「4:12 / 7:30」）、近傍の平均距離。
- **性能の目安：** 2000羽で1回の更新が 12 ms 未満（PC。イワシの T19 と同じ基準）。
